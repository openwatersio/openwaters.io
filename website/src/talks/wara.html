From VHF to vessel tracks

How ships report their position, how a spare SDR can hear them, and how those reports become a map.

Bryan Clark · Open Waters · A 20-minute talk for WARA / VE7VIC

Speaker notes · 0:00–1:15

Hold up the SDR or the whole receiver. “If a ferry comes out of the Strait of Juan de Fuca during this talk, this little box might hear it tell us where it is. The ferry sends the same report to anybody in range. It has no idea we’re listening.”

I run a small AIS receiver in Oak Bay. I got interested in what my antenna could hear, then in what I was missing. AIS stands for Automatic Identification System. Ships use it to share their identity and movement with nearby ships and shore stations. Tonight we’ll follow one report all the way to a map and see what changes when we put the receiver somewhere better.

An iGate for ship reports

WARA’s original VE7VIC-14 already did the familiar part. Hear a beacon over RF and forward it to a shared service.

VE7VIC-14 APRS iGate

144.390 MHz
APRS beacon → receive-only iGate → APRS-IS

Shore AIS station

161.975 / 162.025 MHz
Marine report → receive-only SDR → AIS network

AIS has its own physical layer, time-slot rules, and message formats. The shore box listens on marine VHF and forwards over IP.

WARA’s APRS upgrade write-up

Speaker notes · 1:15–3:00

Ask who remembers the original VE7VIC-14 or has set up an iGate. WARA’s write-up describes it as receive-only. The later VE7VIC-15 at Triangle Mountain also supported digipeating and two-way gating. For this project, the receive-only box is the analogy. There’s no marine transmitter in it, and no return path to the ship.

The iGate analogy gives us useful troubleshooting instincts. You can be hearing RF and failing to forward it. You can be forwarding successfully from a site that hears almost nothing. Those are two different problems, and you can measure them independently.

Two channels, one shared clock

AIS 1 · 161.975 MHz
AIS 2 · 162.025 MHz

9,600 bit/s GMSK on each channel
2,250 slots/min Per channel, about 26.7 ms per slot

Class A uses self-organizing TDMA. Stations track slot use and advertise future slot use as they broadcast. Class B includes both self-organizing and carrier-sense variants.

A moving Class A ship normally sends position every 2–10 seconds, depending on speed and course changes. Its name and other static or voyage data normally arrive every six minutes.

ITU-R M.1371-6 · US Coast Guard AIS overview

Speaker notes · 3:00–5:15

Divide 60 seconds by 2,250 with the room. A common Class A position report fits a slot. Some messages use more than one. A receiver that samples both channels can demodulate them separately since their centers are only 50 kHz apart.

Ask what a hilltop receiver hears that a ship down in the channel might not. A third receiver can be in range of two transmitters that can’t hear each other. Time-slot coordination helps local stations share the channel, and collisions can still occur at a receiver. This matters even before we add internet transport.

Most listeners notice the reporting schedules before they notice TDMA. A new contact may show up as a number and a position. The label fills in when the relevant identity message reaches the receiver.

What’s in one packet?

After demodulation, the receiver can wrap the AIS payload in an !AIVDM sentence. 

!AIVDM,1,1,,A,1>pf7wPP2Uo<2@0KgI0<<?vH0000,0*5D

A synthetic example for the talk. It represents one received Type 1 position report.

Show the decoded fields
MMSI
999000062 (demo value)
Position
48.480° N, 123.200° W
Speed over ground
16.5 knots
Course over ground
312.0° true · heading unavailable

The sentence identifies channel A and carries an ASCII-armored payload. Its final checksum covers the sentence text.

US Coast Guard Class A position-report fields

Speaker notes · 5:15–7:00

Ask what should appear on the map from just this sentence. Reveal the fields. The MMSI is the Maritime Mobile Service Identity, the number we can use to join a position to a later identity report. Here we have speed and course over ground. True heading is unavailable, even though we know which way the vessel is moving.

Point out the layers. The SDR receives a radio burst, the decoder checks the received frame, and this text is a receiver output. The text checksum checks the wrapper for errors. A valid frame and a valid wrapper still leave us with values reported by somebody else’s equipment.

Build it on the bench

A vertical antenna, an RTL-SDR, and a Raspberry Pi running AIS-catcher.

  1. Start with a vertical antenna suited to 162 MHz and a clear view of the water.
  2. Connect the RTL-SDR to a Pi or computer. Install AIS-catcher using the shore guide.
  3. Watch for decoded NMEA locally. Check the vessel viewer before adding an internet output.

Try a local decode

AIS-catcher -o 1

Run this on a bench install with the RTL-SDR selected as the input and available to the process. If AIS-catcher already runs as a service, use its existing viewer.

Once local reports are coming in, add an authenticated output on ordinary internet and check the station’s last-heard time.

Hardware and installation guide · Forward messages and confirm reception

Speaker notes · 7:00–9:30

Pass the receiver around or point out the antenna connection, dongle, USB, and Ethernet. A quarter-wave in free space at 162 MHz is about 46 cm. For a first test, use an antenna at a window facing open water and start with ordinary gain. Compare successful decodes as you make changes. A noisy waterfall or a high signal reading can coexist with very few good packets.

If there are local packets but no upstream activity, check the output settings, logs, and authentication. If there are no local packets, work back from the dongle to the antenna. At a repeater site I’d specifically test whether nearby transmitters overload the front end before deciding on gain or filtering. If the room can hear traffic, show the terminal. Otherwise use the example we just decoded and stay on time.

What if we move the antenna?

A headland can take an entire approach out of earshot. Height helps when it opens a clear path to the water.

Our first comparison would be Oak Bay versus a higher site. Which part of a track starts earlier, and which disappears behind land?

Play with the geometric horizon

Ship antenna fixed at 15 m above the water. Shore antenna starts at 10 m.

25 km · 14 nmi

Smooth-Earth estimate from the sum of both horizons. Terrain, refraction, feed line losses, and interference affect what decodes.

Speaker notes · 9:30–11:45

Ask for a guess before raising the shore antenna from 10 to 100 metres. The simple estimate uses 3.57 times the sum of the square roots of the heights in metres, giving distance in kilometres. That coefficient comes from the tangent to a sphere of radius about 6,371 km. It’s a geometry exercise with no terrain or atmospheric model. The example heights are hypothetical.

Ask what will matter more from a particular site, another 10 m of height or clearing the ridge in the direction we care about. Look for repeatable new sections of track in a weak sector and keep an eye on overlaps and outages. One unusually good propagation evening can make a mediocre site look great.

Three receptions, one vessel update

aiscast is the open-source server behind Open Waters AIS. When three antennas hear the same transmission, it keeps the reception records and sends one vessel update in the live stream.

Receivers add perspective

Overlap keeps the track going if one path drops. A well-placed station can also hear sections of the track the others miss.

Time and source matter

A delayed upload can carry an older position. Inspect when the report was heard and which station or upstream feed delivered it.

aiscast reception and deduplication design

Speaker notes · 11:45–13:15

Imagine Oak Bay hears the burst and two other stations hear it too. The live feed only needs one position update. For coverage analysis, we still care that three stations heard it. Network redundancy and a station’s additional coverage are both useful, and the reception records tell those stories.

What happens to the reports you share?

Your station’s receptions · CC0

By sending your own over-the-air receptions, you dedicate them to the public domain. Anyone can copy, republish, or use them commercially without asking. You can keep feeding other networks.

The volunteer database · ODbL

Anyone can copy, mirror, or build with the combined volunteer database. Credit the source when you use it publicly and share publicly used adaptations of the database under the same licence. Partner feeds keep their own terms.

You can stop feeding at any time. Reports already released stay open. If you include your own vessel’s !AIVDO messages, you also share its position publicly.

AIS Contributor Agreement · CC0 deed · ODbL summary

Speaker notes · 13:15–15:00

“Say your Oak Bay receiver hears a ferry. You can send the same reception here, to a second network, and to a club server. Once you share it with us under CC0, the club down the road can reuse that reception too. Open Waters has the same rights as everyone else. Stopping your feed stops new contributions. It leaves the earlier ones available.”

The share-alike rule applies to the combined volunteer database. If a club edits that database and uses the result publicly, it must offer the adapted database under ODbL. The agreement commits Open Waters to keeping the volunteer database open even if the project changes hands. Use your receiver’s own reports when contributing. If your setup also forwards your boat’s position, review that setting before sending.

Could another club run a mirror?

A station can send the same report to several networks. The terms for passing on what you get back depend on the network.

Open Waters AIS
Yes, for the open volunteer database under ODbL.
AISHub
Its published terms allow credited maps, research, and commercial products. They prohibit passing on raw AIS messages, positions, or tracks from AISHub.
MarineTraffic
Active contributors can request selected vessel or area feeds for personal use. Its business terms require written consent for public redistribution of service data.

Speaker notes · 15:00–16:30

Ask, “If our club wants to pass the reports on to the next club, what can we actually give them?” We can always share our own CC0 receptions. We can also copy or mirror the Open Waters volunteer database under ODbL when we have a copy. Separate partner data by source and follow its terms.

AISHub’s October 2026 terms apply immediately to new members and from January 2027 to existing members. MarineTraffic also says operators using their own receiving equipment can decide where to forward their own data. Its personal-use offer applies to data it sends back to active contributors. Why might the track stop?

Land shadow, a missed burst, a receiver outage, or delayed forwarding can all leave an old dot on the screen. Compare the reception ages of nearby vessels and check whether other stations still hear this one.

Use the internet map for observation. Vessels without AIS are absent, and received positions can be stale or wrong.

Speaker notes · 16:30–18:30

Before the meeting, open the map in another tab, pan to Victoria, and confirm it has recent reports. During the talk, give the audience ten seconds to decide which vessel to inspect. A ferry makes a good example if one is in view, since the route is familiar and it moves far enough to see updates during the demo. Show the last report and the visible track where available, then compare with a station or source view. Make clear which sources the map actually credits.

If the connection is slow, use the walkthrough on this slide. Pause at +42 seconds. “We stopped receiving updates. What else would you look at before deciding what the boat did?” Ask about other targets, other stations, and the age of the last report. The live map is an observation tool. On a boat, AIS is one input alongside lookout, radar, and other navigation information.

Could we try one receiver beside an iGate?

Triangle Mountain and Oak Bay are two places to discuss with WARA’s Technical Committee. A member’s shore-facing antenna could also make a good test site.

What we’d measure

Compare both stations over the same period. Look at useful new stretches of track, overlap, and gaps. Start with the approaches the room knows from Swiftsure.

How we’d connect it

Ordinary internet is the straightforward option. Open Waters accepts plain UDP, but any HamWAN use would need a separate discussion about the club’s policy and our paid hosted service.

Open Waters can supply the receiver. Site access, antenna placement, interference, and backhaul are for the site operators to evaluate.
